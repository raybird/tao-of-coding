# Release v5.0.0

## Highlights
- orchestrator 不再靠 shell 包裝啟動——**當前 agent 本體即 orchestrator**，讀取協議後以宿主原生 subagent（或 in-context）調度角色。框架轉為 host-agnostic，可正當安裝進任何宿主。

## Breaking Changes
- **移除全部 shell 調度 CLI**：`orchestrate-skill.sh`、`skill-dispatch.sh`、`parallel-dispatch.sh`、`loop-dispatch.sh`、`reduce-envelopes.sh`、`run-gc.sh`、`validate-agent-message.sh` 全數刪除。任何以這些腳本或 `--runner-cmd` / `opencode run` 為入口的流程不再適用。
- **移除 Agent Message v1.0 envelope 契約**：刪除 `agent-message.md` / `agent-message.schema.json`；五張角色卡不再要求「最終回覆必須是一段 JSON」。角色改為直接交付摘要 + 可追溯 artifact 路徑。
- **移除自動路由設定與 dispatcher 契約**：刪除 `references/skill-routing.conf`、`docs/skill_dispatcher_contract.md`、`docs/skill_routing_format.md`。路由意圖改以 `SKILL.md` 的「技能路由表」（markdown）表達，由 agent 本體閱讀判斷。
- **協議改寫**：`SKILL.md` `compatibility` 不再要求安裝 `opencode` CLI；新增〈調度方式 (Delegation)〉取代原本的「自動化工具 / 標準調用流程 / Delegated 執行契約」章節。

## Migration Guide
1. **停用所有 shell 派工指令**。原本 `bash .../orchestrate-skill.sh --prompt ... --runner-cmd "opencode run ..."` 的用法不再存在。
2. **改由 agent 本體調度**：讓 agent 讀取 `SKILL.md`（或宿主 `AGENTS.md` 的受管區塊），依「技能路由表」判斷角色，再以**宿主原生 subagent/task**（如 Claude Code 的 Task、opencode 的 agent）委派；宿主無此能力時 in-context 切換角色。
3. **常駐根身份用模式 B**：`bash skills/tao-of-opencode/scripts/install-orchestrator.sh --target <宿主實際讀的 AGENTS.md>`，把受管區塊冪等寫入。
4. **角色輸出**：不再包 JSON envelope；長內容寫到 `docs/...`、`src/...`、`tests/...` 並附路徑即可。
5. 清除任何引用已刪腳本的本機設定（如 `.claude/settings.local.json` 的權限 allowlist）。

## Added
- `skills/tao-of-opencode/scripts/install-orchestrator.sh`：模式 B 安裝工具，仿 GitNexus 把 `<!-- tao:start -->…<!-- tao:end -->` 受管區塊冪等寫進宿主 `AGENTS.md`（冪等／非破壞／`--remove`／`--dry-run`，預設 `./AGENTS.md`、可 `--target`）。
- `SKILL.md` 新增〈調度方式 (Delegation)〉段，定義 host-agnostic 的角色委派模型。

## Changed

- `CLAUDE.md`、`README.md`、`docs/superpowers_playbook.md` 改述為 agent 原生調度；`docs/orchestrator-identity-and-portable-install.md` 標註模式 A 機器已移除。
